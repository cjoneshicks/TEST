# Running the Client Launch Hub locally

This folder is the unmodified ChatGPT Sites export (see `README.md`). The only
additions are this file and `scripts/local-setup.sh`; application source,
config and the lockfile are exactly as exported.

## Stack

- **Vinext 0.0.50**: a Vite 8 reimplementation of the Next.js App Router. The
  code is written against `next` 16.2.6 APIs (`next/headers`, `next/font/google`,
  route handlers) but is built and served by Vite, not `next build`.
- **Cloudflare Workers runtime**: `worker/index.ts` is the Worker entry.
  `@cloudflare/vite-plugin` 1.37.1 runs it in `workerd`/Miniflare during
  `npm run dev`, with the bindings declared in `vite.config.ts`.
- **React 19.2** with React Server Components (`@vitejs/plugin-rsc`).
  `app/page.tsx` is a server component that reads the hosted identity headers;
  `app/portal-client.tsx` is the client UI. Icons come from `lucide-react`.
- **Data**: Cloudflare D1 (SQLite) through `drizzle-orm` (binding `DB`); file
  uploads go to Cloudflare R2 (binding `FILES`). Migrations live in `drizzle/`
  (generated by `drizzle-kit`).
- **Styling**: Tailwind CSS 4 via PostCSS, but nearly all styling is
  hand-written CSS in `app/globals.css`. The Geist fonts are pre-downloaded
  into `.vinext/fonts/`.
- **Tooling**: TypeScript 5.9, ESLint 9 (`eslint-config-next`), `wrangler`
  4.92, and Node's built-in test runner.

## Steps

Requires Node.js >= 22.13 and npm.

```bash
npm ci
bash scripts/local-setup.sh   # once per checkout; re-running is harmless
npm run dev                   # http://localhost:5173
```

On `localhost` there is no ChatGPT sign-in, so the server treats every request
as the "SeatGeek Admin" preview session. The demo sign-in switcher (Admin, CSS,
Client) works as it does in the hosted preview. A fresh database starts empty.
The UI shows its built-in demo workspace and saves it to D1 on the first edit.

## Why `scripts/local-setup.sh` is needed

The hosted Sites platform did two things for the app that the export doesn't
include:

1. **Applied the D1 migrations.** The app never creates its own tables, so on
   a fresh local database `/api/pilot-state` returns 500 ("Pilot storage is
   still being prepared") and `/api/files` returns 503. The script runs
   `wrangler d1 migrations apply --local` against `drizzle/`, using the same
   binding and placeholder database id as `vite.config.ts`, and writes into
   `.wrangler/state`, which is what `npm run dev` reads.
2. **Built from its own path.** `.vinext/fonts/*/style.css` is Vinext's font
   cache. It embeds the absolute path of the original build machine
   (`/workspace/sites/seatgeek-launch-hub`), and Vinext only rewrites URLs that
   start with the *current* project path. Without the fix, every Geist font
   request 404s and text falls back to the system font. The script points
   those two cached CSS files at this checkout. The font files are unchanged.

Because of step 2, `git status` will show those two `style.css` files as
modified after setup. That change is specific to your machine, so don't
commit it.

## Other commands

| Command | Result locally |
| --- | --- |
| `npm test` | Builds to `dist/`, validates the Worker artifact, runs `tests/rendered-html.test.mjs`. Passes. |
| `npx vite preview` | Serves the **built** Worker in workerd with the D1/R2 bindings and the same local state. This is the closest local match to production. |
| `npm run start` | `vinext start` serves the build in plain Node **without** Cloudflare bindings. Pages render, but API routes return 500 ("D1 binding `DB` is unavailable"). Expected: the build targets a Workers host. |
| `npm run lint` | Fails with 4 pre-existing `react-hooks/set-state-in-effect` errors in `app/portal-client.tsx`. They are left alone because fixing them changes app code. |

## Notes

- The startup warning "Unable to fetch the `Request.cf` object" is harmless.
  Wrangler falls back to placeholder geolocation data when it can't reach
  Cloudflare.
- Email notifications stay off unless `EMAIL_NOTIFICATION_WEBHOOK_URL` or
  `RESEND_API_KEY` + `NOTIFICATION_FROM_EMAIL` are provided as Worker
  variables. In-portal notifications work without them.
- To reset local data: stop the server, `rm -rf .wrangler/state`, then rerun
  `bash scripts/local-setup.sh`.
